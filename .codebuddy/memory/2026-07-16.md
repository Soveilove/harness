用户询问知识库在 CodeBuddy IDE 里的使用方式，是否需要 MCP。经调研 CodeBuddy 官方文档（Rules / Skills / Memory / MCP）后确认：

### 关键发现
1. **MCP 不需要**：当前 20 个 MD 文件规模，CodeBuddy 原生 Rules + Skills + Working Memory 三层机制完全够用
2. **Rules 格式问题（P0）**：当前 `memory-loader.md` 是纯 .md，非 CodeBuddy 期望的 `RULE.mdc` 格式（需 YAML frontmatter + alwaysApply 字段），导致核心约束可能被当建议性而非强制
3. **Rules 与 Skills 职责重叠（P1）**：两处都描述加载逻辑，需明确分工——Rules 只放约束，Skills 只放加载逻辑
4. **Skill 缺 references 目录（P1）**：未利用 CodeBuddy 三级加载的第三级（references/ 按需加载）
5. **踩坑库无 resolved 标记（P2）**：已修复坑点和新坑点混在一起

### CodeBuddy 三层机制
- **Rules (alwaysApply: true)**：每次会话强制加载，适合放宪法红线、编码偏好
- **Skills**：description 触发，三级渐进加载（元数据→SKILL.md→references/），适合放知识库
- **Working Memory**：自动注入，`.codebuddy/memory/` 下 MEMORY.md + 每日日志

## 代码地图与同步策略讨论

用户提出三个问题：代码地图是否用第三方工具、以 master 为基准、自动化同步。

### 1. 代码地图：第三方工具 vs 手动 MD
- **结论：不换，互补使用**
- 现有 MD 代码地图核心价值是**业务语义导航**（阅读策略、数据流链路、文件职责表、任务路由），任何第三方工具都生成不了
- 第三方工具（Sourcegraph / code2prompt / VS Code 插件）生成的是**结构分析**（调用图、依赖树），不含业务意图
- 优化策略：CodeBuddy 内置 `codebase_search` 做临时查询，MD 只沉淀稳定高频路由

### 2. 代码地图基准：master 分支
- **结论：分层管理**
- `board-code-map.md` / `board-video-code-map.md` → 以 master 为基准，只记稳定链路
- `recent-work-code-map.md` → 分支特定，feature 合并后清理对应条目，稳定入口提升到专用地图
- 维护流程：feature 分支 → 临时入口写 recent-work → 合并 master → 稳定入口提升到 board-code-map → 清理 recent-work

### 3. 自动化同步：脚本 + Automation
- **结论：同步脚本 + CodeBuddy Automation 提醒，不上 MCP**
- MCP 适合动态查询外部系统（Jira/数据库），文件复制用脚本更可靠
- 已创建 `harness/scripts/bash/sync-harness.sh`，支持 5 个命令：
  - `status` — 查看所有项目同步状态（hash 对比）
  - `diff <项目>` — 对比具体文件差异
  - `pull <项目>` — 中枢 → 项目（分发，保护 feature.json）
  - `pull-all` — 全量分发
  - `push <项目>` — 项目 → 中枢（显示差异，需手动确认）
- 已测试：3 个项目 status 正常，diff 精确检测出 RULE.mdc 缺失和 SKILL.md 差异

## CodeGraph 工具评估

用户询问 CodeGraph 工具是否适合替代 MD 代码地图。经调研后结论：

### CodeGraph 是什么
- 语义代码智能工具（code-graph.pro），用 SQLite + tree-sitter 构建本地代码知识图谱
- 支持 19 种语言，通过 MCP 协议与 Claude Code/Cursor/Codex/Gemini 集成
- 声称减少 92% 工具调用、57% token、46% 响应加速

### 结论：不引入，当前阶段性价比不够
1. **CodeBuddy MCP 兼容性不确定**：CodeGraph 官方未列出 CodeBuddy 支持，需验证协议兼容性
2. **3 个同构 Vue 项目**：CodeGraph 的价值在大仓复杂调用链，3 个相似项目结构高度重复
3. **CodeBuddy 内置搜索已够用**：`search_content` + `search_file` + code-explorer subagent 覆盖结构查询
4. **瓶颈不在结构查询**：核心痛点是 AI 静默漂移和业务逻辑一致性，不是"找不到函数定义"

### 互补关系（未来如引入）
- CodeGraph 查结构：函数调用链、反向引用、跨文件依赖
- MD 地图查业务：阅读策略、数据流链路、任务路由、参数映射
- tree-sitter 自动生成的是代码符号关系，MD 地图沉淀的是人类业务理解，两者无法互相替代

### 引入条件（未来）
- CodeBuddy 明确支持 CodeGraph MCP server
- 项目规模增长到内置搜索不够用
- 团队人数增加，新人需快速理解代码结构
