## 017-node14-compat Feature 启动（工作流）

用户决定通过 Sovei 工作流开发"降低 Node 版本要求"。已 bootstrap `017-node14-compat`（S1 风险，load 阶段）。

### 关键决策（load/grill 确认）
- **目标：严格兼容 Node 14**（公司主流环境），Node 14 已 EOL（2023-04）。
- **发布产物形态：改为 CommonJS**（用户授权"你看着来，反正 Node 14 要能用"）。原因：Node 14 的 ESM 支持有严重缺陷（import.meta.dirname 不可用、node: 前缀部分不可用、条件 exports 支持差），CJS 是 Node 14 最稳定形态。
- **兼容范围：仅发布产物（CLI 二进制）需在 Node 14 运行**（用户：公司电脑用 Node 14 下载 CLI 跑起来）。开发/构建/测试链路仍用 Node 20+。关键依据：发布产物是 esbuild 单文件、零运行时依赖（dependencies 为空），运行时只需内置 API + 降级语法；devDeps（tsc/tsx/esbuild/node:test）只在本机开发用。

### load 阶段盘点出的 Node 14 不兼容点
1. **发布产物是纯 ESM**（package.json "type": "module"）→ 需改 CJS 或双形态。构建：esbuild `target: 'node20'`（build-release.mjs:29）需降。
2. **`import.meta.dirname`**（build-release.mjs:6、clean-dist.mjs:4）→ Node 20.11+，Node 14 不可用。
3. **`.at()`** 3 处：workflow-engine.ts:380/394、business-map-scanner.ts:192 → Node 16.6+，需替换 `arr[arr.length-1]`。
4. **`node:test`** 测试框架（所有 test/*.mjs）→ Node 18+，Node 14 无。测试脚本 `node --test test/*.test.mjs`。
5. **全局 fetch**：src 无 fetch 调用，但 skills installer/upgrader 用 execSync 走 git；网络通道 raw.githubusercontent.com 可用。
6. `node:crypto`/`node:fs/promises`/`node:path`/`node:os`/`node:util`/`node:child_process` 等标准库 Node 14 均有。
7. devDeps：tsx（dev 用）、esbuild、javascript-obfuscator、commander 等需要 Node 14 兼容版本。
8. Node 14 标准库差异：`fs/promises` 的 `readdir`、`FileHandle` 类型；`randomUUID`（crypto.randomUUID，Node 14.17+，需确认 >=14.17）。

### 017 converge 发现并修复高严重度 H1（重要教训）
- 审查子代理发现 `build-release.mjs` 的 externalModules 校验在 CJS 产物下会**必然失败**，实测证实（pnpm run build exit 1）。
- 两层根因：
  1. CJS 模式下 esbuild 剥离 `node:` 前缀，内置模块以 `require("fs")` 等无前缀形式输出；filter 未排除内置模块 → 全部误判为"未内联外部依赖"。banner 注入的 `require('url')` 也被捕获。
  2. 正则 `from\s*` 分支会误匹配**字符串文案**里的 `from '...'`（如 commander 错误消息 `"remove description parameter from '.command()'"`）→ 误抓 `.command()`。
- 修复：用 `isBuiltin`（node:module）过滤内置模块；正则收紧为只匹配 `require(`/`import(`（真实函数调用），移除 `from` 分支。
- 修复后全绿：pnpm run build、107/107 测试、verify:package、Node 14 smoke 全部通过。
- **教训**：改产物 format（esm→cjs）会改变 esbuild 对 `node:` 前缀的剥离行为，所有基于产物文本的校验正则都要重新审视；字符串内文案可能被 import 检测正则误匹配。
