## 诉求三：CLI 交互面板（方案 H）

用户补充第三诉求：**CLI 交互体验**——多选、或不指定参数时要有**操作面板**（空格选择、Enter 确认、↑↓ 导航）。

**关键约束**：`sovei` 是**零运行时依赖**（package.json `dependencies` 空，单文件 `sovei.cjs`），**不能引入 inquirer/prompts 第三方交互库**。交互面板需**自研**：Node 原生 `readline` + 终端转义序列（↑↓ 移动/空格勾选/Enter 确认），内联到单文件，零新增依赖。

**现状痛点**：`adapters install` 无参数时只 `console.log` 打印列表 + 提示手工敲 `--adapters`，无交互面板。同类问题散落 `project init --adapters`、`skills bind` 等。

**方案 H 设计要点**（已写入 DEV_BACKLOG §10.7 + 决策项 D18 + 开发顺序 19）：
- 建 `src/cli/interactive/` 模块，提供 `select`（单选，Enter 确认）和 `multiselect`（多选，空格勾选，Enter 确认）两个原语
- 非 TTY（管道/CI/脚本）自动降级为文本提示，不影响 `--json`/脚本化
- 有参数直接走参数，无参数才弹面板
- 应用：`adapters install`、`project init --agent/--adapters`、`skills bind` 等

**方案 H 是方案 F 的操作前提**（F 的四 agent 选择器需要交互面板）。三个诉求完整关联：诉求一=技能库内容、诉求二=IDE agent 调用、诉求三=人类 CLI 体验。
