## AI 辅助开发方案选型讨论

用户面试遇到公司想做"自我迭代编排 Agent 服务业务开发"的方案，但担忧开发成本（验证准确率、迭代偏移量等）。用户倾向轻量知识库 + 强约束 MD 方案。

### 分析结论
- 编排 Agent 方向没错，但不适合人力不足 + 业务迭代重的场景
- 三个递归难题：验证准确率需要 ground truth（最终靠人）、偏移检测是元问题递归、Agent 维护成本可能 > 业务开发成本
- 用户现有 Harness 体系（`E:\memory` 中枢 + IDE Loader + 业务地图模板）就是轻量方案的可行实例
- 核心优势：事前约束替代事后验证、验证门槛从"逐行读代码"降到"对齐业务红线"、1-2 周见效、可增量上线
- 编排 Agent 适用前提：平台型团队做基础设施给业务团队用，需要 10+ 人专职、业务稳定、6 个月见效周期
