## Feature 016: prepareStage 强制检查

### 问题

外部 Skills 配置了但从未被使用。根本原因：`completeStage` 不检查 `prepareStage` 是否被调用过，AI 可以直接写产物然后 `--complete`，跳过 skill 注入。

### 走完 Sovei 12 阶段工作流（这次每个阶段都先 prepare 再 complete）

- `types.ts`: 添加 `STAGE_PREPARED` 事件 + `preparedStages: string[]` 到 WorkflowState
- `state-machine.ts`: STAGE_PREPARED 添加到 preparedStages；STAGE_COMPLETE 移除；REOPEN/CHANGE_DECLARED 清除目标及后继
- `workflow-engine.ts`: prepareStage 追加 STAGE_PREPARED 事件；completeStage 检查 preparedStages，未 prepare 时 throw
- 6 个现有测试修复（添加 prepare 调用），2 个新测试（throw + prepare-enables-complete）
- 104 tests, 104 pass, 0 fail
- 外部 skill 在 grill/spec/tasks/implement/converge/verify/learn 阶段全部成功注入

### 关键决策

- 用事件溯源追踪 preparation 状态（STAGE_PREPARED 事件），不用副作用文件
- completeStage 在未 prepare 时 throw 而非 warn（warn 会被 AI 忽略）
- 所有 12 阶段都强制 prepare，不特殊对待 load
- 新事件类型是 additive 的，旧 Feature 事件日志不受影响

## Learn 阶段知识自动对账引擎

### 问题诊断

- 14 个 spec 跑完，知识库 14 条全部 candidate，从未晋级过一次
- learning-report.md 写完就躺在 specs/ 目录，没有回流到知识库
- 断裂点：learn 阶段 postExecute 只校验文件存在，不提取观察、不操作知识库

### 实现方案

- **新模块** `knowledge/reconcile.ts`：解析 learning-report.md 中的 `yaml:knowledge-delta` 结构化块，自动对账到知识库
  - 新观察 → ADD 为 candidate
  - 已有条目 + 新证据 → PROMOTE（candidate→pending 需 2 证据，pending→stable 需 3 证据）
  - 标题相似度匹配（normalize + 子串包含 + 词重叠）+ 标签重叠 + relatedEntryId 加速
  - 拒绝模式（category: rejected）不进入知识库
  - 同 Feature 重复证据自动跳过
- **修改 learn 阶段** prompt：要求 AI 在 learning-report.md 末尾产出 `## 知识提取` + `yaml:knowledge-delta` 块
- **修改 learn 阶段** postExecute：调用 reconcileObservations → persist → 写 knowledge-delta.md
- **新增产物** `knowledge-delta.md`：对账报告，记录新增/晋级/自动 stable/跳过/错误
- **新增 CLI** `sovei knowledge review`：按 lifecycle 分组展示，标记自动 stable 条目，提示 deprecate 回退命令
- **设计原则转变**：从"stable 前必须人工审查"（事前阻断）→"3+ 独立 Feature 证据自动晋级 stable，事后可回退"（trust-but-verify）
- **新增测试** `learn-reconcile.test.mjs`：11 个测试覆盖解析、对账、匹配、晋级、报告格式化
- 全部 102 测试通过
