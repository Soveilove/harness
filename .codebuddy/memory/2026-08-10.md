### 子 Agent 强化方向（§2.9，架构观察）
思考 Sovei 工作流中哪些串行 I/O 密集型节点可用子 Agent（sub-agent）并行化：

1. **SA-1 cross-feature 相关性过滤**（P1）：`--cross-feature` 串行遍历所有 Feature 目录读 decision-log，50+ Feature 时瓶颈明显。子 Agent 并行读取 → 各自输出摘要 + 相关性评分 → 主 Agent 取 Top-N。直接解决 P1-3 上下文包膨胀。**优先实施**。
2. **SA-2 context build 组装**（P2）：required 项（红线+知识+规范+产物）串行加载。子 Agent 分组并行加载，主 Agent 合并 + 优先级截断。
3. **SA-3 converge/verify 代码审查**（P2）：单一 Agent 会话做全部审查。子 Agent 分维度并行（类型安全/测试覆盖/规则合规/架构合规），主 Agent 汇总裁决。
4. **SA-4 drift detection 影响面评估**（P1，与 drift MVP 同期）：未实现。子 Agent 按规则类别并行扫描（红线 scope/coverage-matrix/knowledge 证据），主 Agent 汇总 drift 报告。
5. **SA-5 preflight 三类冲突检测**（P2）：当前串行执行红线→知识→coverage，三类互相独立可并行。当前数据量小收益有限，规模化后可提升。
