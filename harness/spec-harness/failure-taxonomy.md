# 失败分类（Failure Taxonomy）

> 对开发失败/返工进行归类，便于在 spec-review 和 retrospective 时快速定位问题类型。
> 可对标 T1-T7 或自定义更适合前端开发的分类。

## 分类

| 类型 | 名称 | 描述 | 示例 |
|---|---|---|---|
| F1 | 数据契约错误 | 字段名、类型、可选/必填、枚举值与后端/协议不一致 | 漏传 `inputVideoDuration` |
| F2 | 状态同步错误 | 多个 ref/store 状态没有同步更新 | 改 `videoModelKey` 没同步 `model` |
| F3 | 分支覆盖遗漏 | 新增分支/条件/场景没覆盖全 | 新增模型没同步映射表 |
| F4 | 生命周期错误 | 组件卸载、监听、订阅、事件清理问题 | 未清理 watcher 导致内存泄漏 |
| F5 | 性能/资源错误 | 大图未压缩、重复请求、未懒加载 | 详情弹窗用完整原图而非缩略图 |
| F6 | 交互/行为错误 | 用户操作流程与产品预期不一致 | 批量模式下点击卡片误打开详情 |
| F7 | 代码结构错误 | 违反项目架构约定（注册表、边界、命名） | 在调用方堆条件分支而非新增模块 |
| F8 | 规则误用/过时 | 使用了已废弃或未经验证的规则 | 用 `!isFlux` 而非 `ckptType === 'A1'` |

## 使用方式

- spec-review 发现偏差时，先标类型，再决定是否提炼规则。
- retrospective 时统计各类型的密度，优先治理高密度的类型。
- 新增失败类型时同步更新本表。
