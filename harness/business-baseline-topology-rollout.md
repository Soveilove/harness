# 业务基线拓扑改造步骤

> 目标：把已验证的 `master` 行为转化为 Coding Agent 可按需读取的业务拓扑，降低代码探索成本，并把未经 Spec 授权的行为变化暴露为风险。
>
> 当前试点：`E:\project\holopix\pino-front` 的 `/workspace/aivideo`（非自由画布 AI 视频生成）。所有试点资产仅本地保存，不提交 Git。

## 不变原则

1. `master` 的固定 commit 是基线证据，不是自动成立的产品真相。
2. 只有人工确认的可观察行为可标为 `baseline`；仅从代码推断的内容标为 `candidate`。
3. 代码图谱只负责结构、调用与影响范围；业务拓扑负责能力、契约、红线与人工证据。
4. Agent 按需加载索引、能力卡和直接依赖契约；禁止全量加载地图。
5. 新 Feature 只能显式修改 `allowed-change` 中的基线行为；其余命中红线的差异均需人工确认。
6. 发布后并经人工验证的行为才可升级为下一版基线。

## 分层模型

```text
业务拓扑（人工确认）
  能力 → 用户旅程 → 共享契约 → 红线 → 证据
      ↓                         ↑
代码知识图谱（自动派生）
  文件 / 符号 / 调用 / 数据流 / Git diff 影响面
```

## 本地试点资产

```text
.baseline-map/
├─ manifest.json                 # 基线 commit、版本、状态
├─ index.md                       # 低 token 业务域索引
├─ topology.md                    # 人类可读的局部业务拓扑
├─ capabilities/                  # 按业务能力拆分
├─ contracts/                     # 跨能力共享的行为契约
├─ features/                      # 每个 Feature 的影响声明
└─ evidence/                      # 手工验证记录与素材引用
```

## 实施阶段

### 阶段 0：冻结试点

- [x] 确认工程与基线分支。
- [x] 记录 `master` commit。
- [x] 选定非自由画布 AI 视频生成作为首个能力切片。
- [ ] 确认视频改版 Feature 的边界与允许变化。

### 阶段 1：建立样板拓扑

- [ ] 创建本地且 Git 忽略的 `.baseline-map/`。
- [ ] 编写 AI 视频生成能力卡：入口、旅程、状态、红线、代码证据、手工验证。
- [ ] 提炼并链接三个共享契约：素材校验、生成任务生命周期、权益与算力。
- [ ] 编写局部 Mermaid 拓扑，使人和 Agent 都能先读概览再下钻。
- [ ] 建立 Feature 影响声明模板。

### 阶段 2：把地图接入开发循环

1. 开始 Feature：读取 `index.md` → 目标能力卡 → 直接依赖契约。
2. 写 Spec：填写影响声明，逐条列出“保持 / 允许改变 / 尚待确认”的红线。
3. 实现中：代码图谱或搜索只用于定位被声明的链路和 diff 影响面。
4. 人工验证：依照能力卡的最小步骤记录结果；不以单测替代业务验收。
5. 上线后：确认的新行为更新为候选基线；人工批准后才提升 `manifest.json` 的基线 commit。

### 阶段 3：渐进覆盖 master

- [ ] 每次 Feature 只补本次触及的能力及新发现的共享契约。
- [ ] 共享契约只维护一份，能力卡通过关系链接复用，禁止复制规则。
- [ ] 每月清理重复、废弃或长期未验证的 `candidate`。
- [ ] 三个工程分别维护项目专属拓扑；只把稳定的模板与通用工作流回灌中央 Harness。

## 衡量试点价值

| 指标 | 记录方式 |
|---|---|
| 首次定位成本 | Agent 读取的文件数、工具调用数、进入实施前耗时 |
| 影响声明完整度 | 实现后发现但 Spec 未列出的受影响能力/契约数量 |
| 静默偏移 | 人工审查或上线后发现的未授权行为变化数量 |
| 维护成本 | 每次更新地图的人工分钟数 |
| 可复用性 | 后续 Feature 直接复用的能力卡/契约数量 |

## 非目标

- 不一次性穷举项目全部业务。
- 不把目录树、完整源码或纯技术架构图当业务地图。
- 不自动把代码推断直接升格为业务红线。
- 不在试点阶段引入单测门禁、Docusaurus 或中心化图数据库。
