# Sovei 文档治理索引

**版本**：0.1
**日期**：2026-08-18

本索引规定不同文档的职责，避免多个文件同时充当“当前真相”。

## 1. 文档职责

| 类别 | 文件/目录 | 用途 | 是否作为当前决策依据 |
|---|---|---|---|
| 产品基线 | `design-docs/产品需求文档.md` | 完整产品定义、用户流程、目标和验收 | 是，产品细节主文档 |
| 产品验证 | `design-docs/产品验证计划.md` | S0/S1/S2 场景和外部验证方法 | 是，验证主文档 |
| 产品模型 | `doc/产品模型.md` | 用用户语言解释产品价值和能力边界 | 是，产品总览 |
| 开发路线 | `doc/开发路线图.md` | 把产品目标转成阶段、依赖和退出条件 | 是，开发排序主文档 |
| 产品功能需求 | `design-docs/产品功能需求.md` | 待重新评估的功能候选、用户问题和验收方向 | 是，产品评估依据；不等于已立项 |
| 历史归档 | `doc/开发归档.md` | 已完成事项、旧设计和历史决策 | 否，只用于追溯原因 |
| 设计背景 | `design-docs/工作流设计.md`、`design-docs/场景决策.md` | 工作流设计背景和场景决策 | 仅用于解释演进背景 |

## 2. 当前唯一产品判断

Sovei 的核心产品任务是：

> 让用户从不完整需求走到有证据的可验证交付，并在每个会话恢复唯一合法下一步。

当前开发先围绕需求进入和状态恢复，不围绕命令数量、Skill 数量或高级图谱能力展开。

## 3. 文档阅读顺序

### 产品理解

1. `doc/产品模型.md`
2. `design-docs/产品需求文档.md`
3. `design-docs/产品验证计划.md`

### 开发决策

1. `doc/开发路线图.md`
2. `design-docs/产品功能需求.md`
3. 对应源码和测试

### 历史追溯

1. `doc/开发归档.md`
2. `design-docs/工作流设计.md`
3. `design-docs/场景决策.md`

## 4. 当前不要做的事

- 不把 `开发归档.md` 当作活跃排期；
- 不把 Allium 示例直接变成 Sovei 状态模型；
- 不让 Markdown、旧事件或旧 YAML 反向决定当前状态；
- 不为了消除历史测试失败而恢复废弃协议；
- 不在没有场景证据时新增节点、Skill、Adapter 或 Graph 能力；
- 不同时启动多个主线 Feature。

## 5. 原始资料处理原则

本轮保留的主资料职责如下：

- `design-docs/产品功能需求.md` 保持待评估产品需求；
- `doc/` 保持产品治理、历史归档和必要专项文档；
- `design-docs/` 保持 PRD、验证计划和设计背景。

不属于当前产品主线、且没有被运行时代码或当前主文档依赖的资料可以删除，不再为了“可能以后有用”长期保留。
